# AI 提案画面 設計メモ

- 対応ユースケース：[docs/ai/api/usecase.md](../api/usecase.md) UC-01〜02
- 対応API：[docs/ai/api/overview.md](../api/overview.md) / [docs/ai/api/request-response.md](../api/request-response.md) / [docs/ai/api/endpoints.md](../api/endpoints.md) / [docs/ai/api/error.md](../api/error.md)
- パス：`/ai`（`docs/design.md` P07）
- 目的：ログインユーザーの学習記録をもとに「次に学ぶべき技術」を提案し、また任意の目標を実装タスクに分解する

---

## 画面が扱う2つの機能

AI 機能のエンドポイントは2本あり、1画面をタブで分けて提供する。

| タブ | エンドポイント | 入力 | 出力 |
|---|---|---|---|
| 学習提案 | `POST /api/ai/suggest` | なし（ユーザーIDは JWT から） | 技術の提案3件（`title` と `reason`） |
| タスク分解 | `POST /api/ai/decompose` | 目標テキスト `goal`（1〜200文字） | 実装順に並んだタスクの文字列リスト |

## 学習提案タブ（`POST /api/ai/suggest`）

### 操作

- ボタン「提案を生成する」1つ。押すとリクエストボディなしで `POST` する
- レスポンスの `suggestions`（`{ title, reason }` の配列。通常3件）をカードで縦に並べる
- レスポンスに `message` が入っている場合（学習記録が0件のとき、サーバーが OpenAI を呼ばずに返す）は、カードの代わりにそのメッセージをそのまま表示する
  - 例：「学習記録がまだありません。記録を追加すると提案が表示されます。」
  - このとき `suggestions` は空配列

### レスポンス形状（`docs/ai/api/request-response.md` と `SuggestResponse` DTO）

```json
{
  "suggestions": [
    { "title": "Docker", "reason": "Spring Bootの学習が進んでいるため…" }
  ],
  "message": null
}
```

- `message` は `null` のときレスポンスJSONからキーごと省略される（`@JsonInclude(NON_NULL)`）。フロントは「`message` があればそれを表示、なければ `suggestions` を表示」で分岐する

### キャッシュの注意（重要）

- サーバー側で提案結果をユーザー単位でキャッシュしている（`@Cacheable`。同一ユーザーの2回目以降は OpenAI を呼ばず前回結果を返す）
- そのため「生成する」を押し直しても内容が変わらないことがある。UI では「前回の提案を表示中」と分かるように、生成日時やキャッシュ由来の注記を出すか、少なくとも「毎回新しい結果が出る」と誤解させない文言にする
- フロントの TanStack Query 側も、`useQuery` ではなく **ボタン押下で発火する `useMutation`** で扱う（画面表示だけで自動的に OpenAI コストを発生させないため）

### レート制限

- 1ユーザー1日10回まで（`suggest` と `decompose` の合計。`AiService` の `MAX_REQUESTS_PER_DAY`）
- 超過すると `429`。メッセージ例：「本日のAI利用上限（10回）に達しました。明日また試してください」
- 同じユーザーが処理中に連打した場合も `429`（「処理中です。しばらく待ってから再試行してください」）。ボタンを生成中 disabled にすれば通常は起きない

## タスク分解タブ（`POST /api/ai/decompose`）

### 操作

- 1行テキスト入力 + 「分解する」ボタン
- レスポンスの `tasks`（文字列の配列）を番号付きリストで表示する。順序に意味がある（実装順）ので `<ol>` で出す

### リクエスト / レスポンス

```json
// リクエスト
{ "goal": "JWTログインを実装したい" }

// レスポンス
{ "tasks": ["User エンティティと UserRepository を作成する", "…"] }
```

- 結果はキャッシュされない（`goal` が毎回違うため）。押すたびに OpenAI を呼び、レート制限のカウントも進む

## 入力・バリデーション（`docs/ai/api/error.md` と対応）

| タブ | クライアント側チェック | サーバーエラー→表示 |
|---|---|---|
| 学習提案 | なし（入力欄がない） | 学習記録0件 → `message` を表示（エラーではない） |
| タスク分解 | `goal` が空なら「分解する」を disabled。200文字超で入力時にカウンタ表示 | 400 →「目標は200文字以内で入力してください」等をフォーム直下に表示 |
| 共通 | 生成中はボタンを disabled | 429 → 上限メッセージ。500 →「AIの応答を取得できませんでした。もう一度お試しください」 |

---

## 状態パターン

- 初期（未生成）：結果エリアに「まだ提案がありません。ボタンを押すと生成されます」
- 生成中：ボタンを「生成中...」にして disabled。結果エリアにスピナー＋「AIが分析しています（数秒〜30秒かかります）」
  - OpenAI の応答は数秒かかり、サーバー側のタイムアウト目安は30秒（`docs/ai/api/endpoints.md`）。フロントの axios タイムアウトもそれに合わせて長め（35秒程度）に設定する
- 成功：結果を表示
- エラー：`429` はレート制限メッセージ、それ以外は汎用エラー＋「再試行」ボタン

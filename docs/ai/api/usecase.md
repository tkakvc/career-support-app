## UC-01　参考資料を生成する

**アクター:** ログイン済みユーザー
**目的:** 興味のある技術・分野、直近の学習記録、または特定の学習記録をもとにWeb検索を行い、関連する最新情報を取得し、要約とタグ分類がされた参考資料を得る
**事前条件:** JWT 認証済み

**正常フロー:**
1. 参考資料の生成をリクエストする（`POST /api/ai/references`、`interest`（任意、200文字以内）・`recordId`（任意、学習記録の詳細画面から生成する場合のみ）を含められる）
2. `recordId`が指定されていれば必ずジョブを作成する。指定が無い場合、学習記録が1件以上、または `interest` が入力されていれば、サーバーはジョブを作成してSQSに積み、`202 Accepted` と `jobId` を即座に返す
3. クライアントは `GET /api/ai/jobs/{jobId}` を数秒おきにポーリングする
4. バックグラウンドで検索クエリを組み立てる。`interest`と学習記録（`recordId`指定時はその記録のタグを優先）は「どちらか一方」ではなく組み合わせる。組み立てたクエリでWeb検索を行い、得られた記事とあわせてOpenAIに送信し、Markdown形式の要約を生成する。`recordId`指定時は、その記録の内容をプロンプト内で「参考資料を作るきっかけになった学習記録」として直近の学習記録一覧とは別枠で最優先扱いする。生成したMarkdownをHTMLに変換し、参考リンク一覧・分類先のタグとともに保存する。完了するとジョブの状態が `DONE` になり、次のポーリングで結果が返る
5. `recordId`が指定されておらず、学習記録が0件、かつ `interest` も未入力であれば、ジョブを作らずWeb検索・OpenAIも呼ばず、固定メッセージ（`message` あり）を`200`で即返す

**タグ分類の扱い：** 既存タグ（大文字小文字を無視した名前一致）に一致すればそのタグを付ける。一致しない場合、**その場ではタグを新規作成しない**。AIが提案したタグ名だけを`suggestedTagName`として保存し、実際の作成はユーザーが「学習記録をつける」を押した時点（`POST /api/tags`経由）まで行わない。非同期ジョブがAIの判断だけでユーザーのタグを勝手に作ってしまうのは、既存のタグ作成（`TagService.createTag`）が常にユーザー起点であることとの一貫性が無いための設計判断。

**例外フロー:**
- `interest` が200文字を超える → 400
- `interest` に禁止パターン（プロンプトインジェクションの典型文言）または有害コンテンツと判定される内容が含まれる → 400
- `recordId` が存在しない、または他人の学習記録である → 404（存在しないケースと区別しない）
- 同一ユーザーの未完了ジョブ（`PENDING`/`PROCESSING`）がすでに存在する（連打） → 429
- そのユーザーの当日のAI利用回数が10回に達している → 429
- Web検索APIがエラーまたはタイムアウトになった → ジョブが `FAILED` になる
- OpenAI API 自体がレート制限に達した → 429（ジョブ作成前の時点で判明した場合。ジョブ作成後に判明した場合はジョブが`FAILED`になる）
- OpenAI 呼び出しがタイムアウトまたは5xxで、1回のリトライ後も失敗した → ジョブが `FAILED` になる
- OpenAI のレスポンス（Markdown）のパースまたはHTML変換に失敗した → ジョブが `FAILED` になる
- 認証トークン不正 → 401
- 存在しない、または他人の `jobId` を指定した → 404

**受け入れ基準:**
- WHEN ユーザーが`recordId`を指定して参考資料の生成をリクエストしたとき THE SYSTEM SHALL 学習記録・interestの有無によらずジョブを作成してSQSに積み、`202` と `jobId` を返す
- WHEN ユーザーが`recordId`を指定せずに参考資料の生成をリクエストし、学習記録が1件以上または `interest` が入力されているとき THE SYSTEM SHALL ジョブを作成してSQSに積み、`202` と `jobId` を返す
- WHEN ユーザーが`recordId`を指定せずに参考資料の生成をリクエストし、学習記録が0件かつ `interest` も未入力のとき THE SYSTEM SHALL ジョブを作らず、Web検索・OpenAI を呼ばず、固定メッセージ付きの応答を`200`で返す
- WHEN バックグラウンドでの生成が完了したとき THE SYSTEM SHALL ジョブの状態を `DONE` にし、要約HTML・参考リンク一覧・分類先のタグ（またはタグ提案名）を結果として保存する
- WHEN AIが提案したタグ名が既存タグに一致しないとき THE SYSTEM SHALL タグを新規作成せず、提案名だけを結果に含める
- WHEN クライアントが `GET /api/ai/jobs/{jobId}` を呼び、ジョブが `DONE` のとき THE SYSTEM SHALL 保存済みの結果を返す
- IF `interest` が200文字を超えるとき THEN THE SYSTEM SHALL 400 を返す
- IF `interest` に禁止パターンまたは有害コンテンツと判定される内容が含まれるとき THEN THE SYSTEM SHALL 400 を返す
- IF `recordId` が存在しない、または他人の学習記録であるとき THEN THE SYSTEM SHALL 404 を返す
- IF 同一ユーザーの未完了ジョブがすでに存在するとき THEN THE SYSTEM SHALL 429 を返す
- IF そのユーザーの当日のAI利用回数が10回に達しているとき THEN THE SYSTEM SHALL 429 を返す
- IF Web検索がエラーまたはタイムアウトになったとき THEN THE SYSTEM SHALL ジョブの状態を `FAILED` にする
- IF OpenAI 呼び出しがタイムアウトまたは5xxで1回のリトライ後も失敗したとき THEN THE SYSTEM SHALL ジョブの状態を `FAILED` にし、「現在AIサービスが利用できません。しばらく経ってから再度お試しください」を持たせる
- IF OpenAI のレスポンス（Markdown）のパースまたはHTML変換に失敗したとき THEN THE SYSTEM SHALL ジョブの状態を `FAILED` にする
- IF 認証トークンが不正のとき THEN THE SYSTEM SHALL 401 を返す
- IF `jobId` が存在しない、または他人のジョブであるとき THEN THE SYSTEM SHALL 404 を返す

## UC-02　保存済み参考資料を一覧・タグ絞り込みで見る

**アクター:** ログイン済みユーザー
**目的:** 過去に生成した参考資料をいつでも見返し、タグで絞り込む
**事前条件:** JWT 認証済み

**正常フロー:**
1. `/ai`画面を開くと `GET /api/ai/references` が呼ばれ、保存済みの参考資料が生成日時の新しい順に一覧表示される
2. タグ絞り込みセレクトでタグを選ぶと `GET /api/ai/references?tag={tagId}` が呼ばれ、そのタグが付いた参考資料だけに絞り込まれる
3. カードをクリックすると、その参考資料の詳細（iframeでの要約表示・参考リンク・「学習記録をつける」フォーム）が表示される。生成直後の表示と同じ画面を再利用する

**受け入れ基準:**
- WHEN `GET /api/ai/references` が呼ばれたとき THE SYSTEM SHALL そのユーザーの参考資料を生成日時の降順で返す
- WHEN `tag`クエリパラメータが指定されたとき THE SYSTEM SHALL そのタグが付いた参考資料だけに絞り込んで返す

---

- 学習記録の詳細画面から特定の記録を起点に生成する導線（`recordId`）がある
- タグの新規作成は非同期ジョブでは行わず、ユーザー起点の操作（学習記録をつける）まで遅延させる設計にしている
- 一覧取得（`GET /api/ai/references`）をUC-02として追加した

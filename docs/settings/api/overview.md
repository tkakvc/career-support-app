# 設定API 概要

このAPIは、ログインユーザー自身のアカウント情報（プロフィール・パスワード）を確認・変更するためのものです。

`docs/design.md` の P08 設定画面（`/settings`）、要件定義 F02 ユーザー管理に対応します。

## 主な機能

- 自分のプロフィール情報の取得（メールアドレス・表示名・作成日時）
- 表示名の変更
- パスワードの変更（現在のパスワード確認あり）

## スコープ外（将来拡張）

| 項目 | 理由 |
|---|---|
| メールアドレスの変更 | 変更確認メールの送信基盤が必要。MVPでは固定とする |
| 2要素認証（TOTP）の設定 | シークレット発行・QR表示・検証・リカバリコードなど実装量が大きい。専用機能として別途検討する |
| アカウント削除（退会） | 学習記録・添付ファイルのカスケード削除とストレージ掃除の設計が必要。別途検討する |

## 共通仕様

| 項目 | 内容 |
|---|---|
| ベース URL | `/api` |
| 認証 | `Authorization: Bearer {JWT}` ヘッダー必須（認証不要のエンドポイントはない） |
| 操作対象 | 常に「トークンのユーザー自身」。他ユーザーを指定する経路は用意しない |
| Content-Type | `application/json` |
| レスポンス形式 | JSON |
| 文字コード | UTF-8 |

## 認可の考え方

- エンドポイントのパスに `{userId}` を含めず、すべて `/api/users/me` とする
- 「誰の情報を触るか」は URL ではなく JWT（`@AuthenticationPrincipal` で受け取る `userId`）だけで決まる
- これにより「他人のIDを入れて他人の情報を書き換える」経路が原理的に存在しない

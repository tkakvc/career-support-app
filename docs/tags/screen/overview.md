# タグ管理画面 設計メモ

- 対応ユースケース：[docs/tags/api/usecase.md](../api/usecase.md) UC-06〜09
- パス：`/tags`（`docs/frontend/design.md` の画面一覧に既定義）
- 目的：ユーザーが自分の学習記録に付けるタグを一覧・作成・編集・削除できるようにする

---

## 表示項目

- タグ一覧をテーブル形式で表示（`GET /api/tags` のレスポンスをそのまま使う）
  - 列：タグ名（`Tag.name`）／種別（`Tag.type`：`default`なら「既定」、`user`なら「独自」）／作成日（`Tag.createdAt`）
- **並び替え**：列ヘッダー（タグ名／種別／作成日）をクリックすると、その列でソートする
  - クリックのたびに昇順→降順を切り替える。現在のソート列・向きは矢印アイコンで示す
  - 初期表示は「作成日・昇順」（先に作ったものが上）
  - ソートはクライアント側で行う（`GET /api/tags` はソート済みで返さない。`docs/tags/api/request-response.md` 参照）。一覧の全件を一度に取得している前提なので、フロントの `Array.sort()` で足りる

## 操作

- **新規作成**：一覧の上に「タグ名を入力して追加」の1行フォーム（別画面・別モーダルにしない。GitHub Labelの追加UIと同じ発想で、その場で完結させる）
- **編集**：`type === "user"` の行にだけ「編集」ボタンを出す（`default` には出さない＝403になる操作をそもそもUIに出さない）
  - 押すとタグ名がテキスト入力に変わるインライン編集（別ページに飛ばさない）
- **削除**：`type === "user"` の行にだけ「削除」ボタンを出す
  - 確認ダイアログを挟む（学習記録の紐付けが解除される旨を一言添える。UC-09の「学習記録自体は消えない」を利用者に伝える）

## 入力・バリデーション（`docs/tags/api/error.md` と対応させる）

| 操作 | クライアント側チェック | サーバーエラー→表示 |
|---|---|---|
| 作成・編集 | 空文字なら送信ボタンを無効化、50文字超で入力時にカウンタ表示 | 409（同名重複）→「同じ名前のタグがすでにあります」をフォーム直下に表示 |
| 編集・削除 | `default` タグにはボタンを出さないので基本発生しない | 403が万一返ったら「このタグは編集・削除できません」を汎用エラーとして表示 |

## 使用API

| 操作 | API |
|---|---|
| 一覧表示 | `GET /api/tags` |
| 作成 | `POST /api/tags`（`TagCreateRequest { name }`） |
| 編集 | `PUT /api/tags/{id}`（`TagUpdateRequest { name }`） |
| 削除 | `DELETE /api/tags/{id}` |

## 状態パターン

- 初回ロード中：一覧部分をスケルトン表示（他画面と揃える）
- タグ0件：`user` タグが1つも無い状態はありうる（`default` は必ずある想定）。「まだ独自タグはありません」の空状態メッセージは`user`タグ側のみに出す
- 作成・編集・削除の実行中：ボタンを disabled にして二重送信を防止（loginページの `isSubmitting` と同じパターン）
